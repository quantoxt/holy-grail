## The Mission

Build a multi-layered, AI-enhanced algorithmic trading system for Deriv's synthetic indices. Not a "set and forget" bot — an **Autonomous Hedge Fund** that requires oversight, continuous optimization, and intelligent risk management.

## Core Premise

Deriv synthetic indices are generated by a **Cryptographically Secure Random Number Generator (CSRNG)**. They mimic real-world volatility but are **unaffected by news, geopolitics, or economic events**. Technical analysis works because the algorithm is programmed to follow patterns — but the "House" maintains a mathematical edge long-term.

Our edge: **Kronos foundation model fine-tuned on Deriv data + dynamic risk scaling** to exploit high-probability windows and survive everything else.

## The Shift: From Indicators to Foundation Model

Originally, Holy Grail planned to use hand-coded technical indicators (EMA, RSI, Bollinger Bands) for signal generation and HMM/XGBoost for regime detection. **That approach is replaced.**

Instead, we use **Kronos** — the first open-source foundation model for financial candlesticks (AAAI 2026, MIT license). Kronos treats OHLCV data as a language: a specialized tokenizer quantizes candles into discrete tokens, and a decoder-only Transformer autoregressively predicts future candles.

**Why this is better:**
- No indicator parameter tuning (no EMA periods, no RSI thresholds to agonize over)
- Model learned price patterns from 45+ global exchanges — understands candlestick "language"
- Fine-tune on Deriv data → domain-specific predictor
- Kills the Phase 0 blocker (strategy selection) entirely
- Implicit regime detection through prediction confidence/variance

**Critical requirement:** Kronos was trained on real exchange data, not CSRNG-generated synthetics. **Fine-tuning on Deriv historical data is mandatory, not optional.** The model must learn the specific microstructure of synthetic indices before any trading.

## The Three Layers (Kronos-Era)

| Layer | Name | Role | Speed | Changed? |
|-------|------|------|-------|----------|
| 1 | **Soldier** (Execution + Prediction) | Kronos inference per candle → thin signal layer → emotionless execution | Seconds (per candle close) | **Major redesign** — Kronos replaces indicator engine |
| 2 | **Watcher** (Confidence Layer) | Extract regime from Kronos prediction variance + error tracking → Kill switch | Seconds (per prediction) | **Replaced** — no more HMM/XGBoost, regime derived from Kronos output |
| 3 | **Sentinel** (Risk & Confidence Manager) | Monitor performance → Scale lot size → Kill switches → Telegram alerts | Minutes | **Unchanged** — but better fuel from Kronos confidence |

## Key Principles

- **Prediction-first execution** — Kronos predicts future candles, thin logic decides trade/no-trade
- **Regime-aware** — bot stops trading when Kronos prediction confidence drops (high variance output)
- **Confidence scaling** — small lots normally, scale up when Kronos is confident
- **Continuous monitoring** — not passive income, it's an active fund
- **Fine-tune before trade** — no live trading without Deriv-specific fine-tuned model

## Mandatory Steps Before Any Trading

1. **Collect Deriv historical tick data** — use Deriv API to pull months of tick history for target indices
2. **Build tick → OHLCV pipeline** — aggregate ticks into clean M1/M5 candles
3. **Fine-tune Kronos on Deriv data** — use finetune_csv pipeline, train tokenizer + predictor
4. **Validate fine-tuned model** — walk-forward backtest on held-out Deriv data
5. **Benchmark inference latency** — ensure predictions complete within candle interval
6. **Build prediction → signal logic** — threshold-based BUY/SELL from predicted OHLCV
7. **Demo trade for minimum 1 month** — log everything, compare predictions vs actual
